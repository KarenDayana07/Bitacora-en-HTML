## 3. Reglas y Compromisos del Equipo
Para evitar conflictos en el código (Git) y asegurar la calidad del entregable, nos comprometemos a:

1.  **Uso de Ramas (Branching):** Ningún integrante trabajará directamente sobre la rama principal (`master` o `main`). Cada uno creará ramas independientes para sus características (ej. `feature/vista-informacion`).
2.  **Conventional Commits:** Todos los mensajes de commit seguirán el estándar (usando prefijos como `feat:`, `fix:` o `docs:`).
3.  **Revisión antes del Merge:** Antes de unir una rama a la principal, la líder del repositorio (Karen) verificará que el código HTML no tenga errores estructurales.
4.  **Accesibilidad y Semántica:** Todo el código que se escriba debe cumplir con las etiquetas semánticas (`<header>`, `<main>`, `<table>`) y los atributos de accesibilidad (`alt`, `lang`, `scope`, `aria-label`) exigidos por la guía.
5.  **Sincronización Constante:** Antes de empezar a trabajar, cada integrante deberá actualizar su repositorio local (usando `git pull origin master`) para evitar trabajar sobre código desactualizado.
